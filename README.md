# CreatureCurios 后台按键器 v3.6.1

Windows 桌面小工具：绑定 `CreatureCurios` 窗口后，在后台循环投递 `A`
（可选空格拾取），可选技能、喝药、疲劳检测、定时提醒，支持**自动打BOSS**、**后台回放（不抢鼠标键盘）**，
并支持**最多 4 开**、**血量保护**和**角色名识别显示**。

## 安装

要求 Windows + Python 3.10 及以上。

```bat
cd F:\jiaoben\3
pip install -r requirements.txt
```

## 运行

```bat
python creature_curios_keyer.py
```

已打包版本：

```text
dist\CreatureCuriosKeyer.exe
```

> 如果游戏以管理员权限运行，本程序也要右键「以管理员身份运行」，
> 否则 `PostMessage` 可能被 Windows 权限隔离拦截。

## 一、基础挂机

- **绑定窗口**：扫描标题包含 `CreatureCurios` 的可见窗口，选择后点「绑定」。
- **每轮间隔**：默认 250ms，最小 50ms，运行中修改立即生效。
- **循环动作**：`A 按下 50ms → 松开`；
  - 勾选「拾取物品（A 后按空格）」时，再追加 `空格按下 50ms → 松开`；
  - 不勾选时只按 A。
- **技能**：可选自动发送 `1`（12 秒）和 `2`（6 秒）。
- **喝药**：可选自动发送 `Q`，默认间隔 60 秒。
- **疲劳检测**：框选右下角会弹出疲劳提示的图标/按钮，每 30 秒点击并 OCR
  读取 `当前疲劳值:xxx/xxx`。
- **疲劳阈值 ±**：默认 800，范围 50～1000；低于 `-阈值` 或高于 `+阈值` 时提醒。
- **定时提醒**：倒计时或指定时刻，最小化到托盘也会弹窗。
- **全局热键**：`Ctrl + Alt + F8` 开始/停止；最小化/关闭窗口驻留托盘。

### 血量自动吃药（Q + W）

单开页和多开页都支持：

- 勾选「血量低于阈值自动吃药（Q+W）」；
- 阈值默认 **1600**；
- 需要先框选血量区域（框住头像旁的当前血量数字）；
- 血量低于阈值时，按「自动喝药 Q」的间隔发送：
  - `Q` 按下/松开；
  - `W` 按下/松开；
- **启用后不再按固定间隔喝药**，只按血量触发；
- 只要血量还低于阈值，就**每隔 Q 间隔继续喝 Q+W，直到血量高于阈值**；
- Q 间隔默认 60 秒，所以两次吃药之间会等待 Q 间隔；想更快可把间隔调小（最小 5 秒）；
- 单开用单开页的血量区域；多开所有窗口共用多开页的血量区域；
- 血量 OCR 失败或窗口最小化时不会触发；
- 游戏窗口请保持不最小化。

## 二、自动打BOSS

BOSS 功能建立在基础挂机之上，**单窗口**运行。有两种方式：

### 方式 A：整段录制回放（推荐，最简单）

把「前往 BOSS → 打 BOSS → 拾取 → 回打怪点」完整录一遍，之后按触发条件
整段回放。

录制：

1. 绑定游戏窗口；
2. 点「录制新脚本」，3 秒内切到游戏；
3. 从站桩点开始完整操作一遍：走到 BOSS、打 BOSS、拾取、返回；
4. 操作完切回本窗口，点「停止录制」；
5. 输入名字保存。

录制只记录**游戏在前台、鼠标在游戏窗口内**的操作，不会录到本程序或其它窗口。

回放：

- 在「录制」下拉框选择刚保存的脚本；
- 点「试放」验证；
- 「打一次BOSS」：只执行一次；
- 「开始BOSS循环」：按「重复」次数执行，`0 = 无限`；
- 「每轮间隔」：两次回放之间等待的秒数；
- 「回放速度」：50%～200%。

> 回放会切换到游戏前台并接管真实鼠标键盘，回放期间不要操作电脑。
> 按 `Ctrl+Alt+F8` 或「停止BOSS」可随时停止。
> 回放前会把游戏切到前台；如果浏览器抢占前台，程序会立即停止，避免误操作。
>
> 如果录制里包含**鼠标转镜头/走位**：
> - 建议关闭「后台模式」，使用**前台绝对模式**；
> - 回放前回到录制时的**起始位置和朝向**；
> - 保持游戏窗口大小和录制时一致；
> - 「前台相对鼠标」镜头更准，但会移动真实鼠标并占用前台，无法边用电脑边挂机。

### 方式 B：识别战斗（导航 + 自动打 + 返回）

录制两小段导航，把战斗交给识别：

1. **前往BOSS录制**（可选）：从打怪点走到 BOSS 前，停止；
2. **返回打怪点录制**（可选）：击杀后拾取并走回打怪点，停止；
3. 在「识别战斗」里分别选择这两段录制（可以不选）；
4. 点「框选区域」，框住能判断 BOSS 是否死亡的区域：
   - **血量数字**：BOSS 血条上的数字，例如 `12345/50000`；
   - **文字/名称**：BOSS 名称或血条文字；
5. 选择「检测方式」：
   - `血量数字`：OCR 解析 `x/y`，当前血量 ≤「击杀血量」时判定死亡；
   - `BOSS 文字/名称`：连续识别不到文字时判定死亡；
6. 设置「连续未识别」次数（默认 2，防止 OCR 抖动误判）；
7. 设置「战斗上限」（默认 180 秒，防止卡死）；
8. 设置「击杀后拾取」次数（默认 3 次空格）；
9. 点「打一次BOSS」或「开始BOSS循环」。

识别战斗流程：

```text
回放“前往BOSS录制”（可选）
→ 用基础页的 A / 技能 / 喝药 自动战斗
→ BossWatcher 每 1.5 秒截图 + OCR 检测
→ 判定击杀：停手 → 按空格拾取 N 次
→ 回放“返回打怪点录制”（可选）
→ 完成一轮
```

识别使用后台 `PrintWindow` 截图，不会移动鼠标；OCR 使用 RapidOCR。

### 触发方式

- **手动**：`打一次BOSS` / `开始BOSS循环`；
- **疲劳触发**：勾选「疲劳低于阈值时自动打BOSS」。
  需要基础页勾选「疲劳检测」并框选区域。
  疲劳 < `-阈值` 时：暂停打怪 → 执行 1 次 BOSS 方案 → 完成自动恢复打怪；
- **定时触发**：勾选「定时打BOSS」并设置分钟数，每隔 N 分钟执行 1 次；
- 疲劳 / 定时触发固定执行 **1 次**；「重复」次数只对 `开始BOSS循环` 生效。

## 三、多开挂机

「多开挂机」页最多同时管理 **4 个游戏窗口**，每个窗口独立执行：

```text
打怪 → 定时检测疲劳 → 疲劳 < -阈值 → 回放 BOSS 录制 → 播完恢复打怪
     → 血量低于回血红线 → 排队回血 / 停平A
```

### 1. 绑定窗口与角色名

1. 先把游戏客户端都打开；
2. 到「多开挂机」页点「刷新窗口」，程序会自动把找到的窗口分配到 4 个槽位；
3. 也可以在每个槽位的「游戏窗口」下拉框手动选择；
4. 先点一次「框选角色名区域」，框住窗口里显示角色名的位置；
5. 之后每次绑定/刷新窗口，程序都会自动 OCR 读取该窗口的角色名并显示：
   - 读取成功：`角色: 张三`（绿色）
   - 读取失败：`角色: 识别失败`（橙色）
6. 也可以随时点「读取全部名字」重新读取。

> 角色名区域和血量区域都是**一次框选、4 个窗口共用**，
> 程序会按每个窗口的客户区尺寸自动缩放。

### 2. 每个窗口的设置

- **BOSS 录制**：该窗口疲劳到阈值时播放的录制；
- **本地挂机**：只后台打怪，不检测疲劳、不播录制；
- **疲劳阈值 ±**：每个窗口独立；
- **喝药间隔**：每个窗口独立；是否喝药仍由单开页「自动喝药 Q」控制；
- **优先级**：1 最高。多个窗口同时要打 BOSS / 回血时排队；
- **回血录制**：每个窗口自己的回血脚本（录制回城 → 回血 → 回打怪点）。

### 3. 血量保护

1. 勾选「启用血量保护」；
2. 点「框选血量区域」，框住头像旁的当前血量数字（如 `1725/1780` 中的 `1725`）；
3. 设置两条线：
   - **回血红线**（高，默认 600，最低 300）：勾选“需要回血脚本”时，
     血量低于它 → 请求回血；不勾选时不会回血；
   - **停平A红线**（低，默认 300）：血量低于它 → 只暂停发 A，
     技能 1/2、喝药 Q 继续；
4. 「需要回血脚本（可选）」：
   - **默认不勾选**：不需要任何回血录制，低血只按停平A红线停手，不播放回血；
   - 勾选后才需要每个窗口选择/录制回血脚本，低血时排队播放回血；
5. 只有勾选「需要回血脚本」后，每个窗口的「回血录制」下拉框和按钮才可用。
   点「录制回血」，3 秒内切到游戏，完整操作一遍回城回血，
   切回程序点「停止录制」并命名。录好的回血脚本只出现在「回血录制」下拉框。

规则：

- 只影响低血窗口，其他窗口继续打怪；
- 如果另一个窗口正在播 BOSS、前台被占用，低血窗口继续打怪，
  回血请求以最高优先级排队；
- 血量掉到停平A红线以下时，该窗口停止发 A，技能/喝药继续；
- BOSS 录制/回血播放期间，该窗口暂停血量检测，不会打断正在播放的录制；
- 回血请求不会切断正在播放的 BOSS 录制。

### 4. 开始 / 停止

- 每个窗口点「开始」，或点「全部开始」；
- 「试放」只播放一次该窗口的 BOSS 录制；
- 「停止」/「全部停止」停止多开；
- 全局热键 `Ctrl+Alt+F8`：
  - 多开运行中 → 停止全部多开；
  - 回血录制中 → 停止录制；
  - 单开 BOSS/挂机中 → 停止对应任务。

> 多开运行期间不能启动单开挂机/自动BOSS；单开运行期间也不能启动多开。
> 同一游戏窗口不能被两个槽位同时使用。

### 5. 前台操作排队

录制回放、疲劳检测点击都需要独占前台鼠标键盘，4 个窗口共用
`ForegroundArbiter`：

- 同一时间只允许一个窗口执行前台操作；
- 多个窗口同时请求时按 **优先级** 排队；优先级相同按请求先后；
- 其他窗口的后台打怪不受影响，继续打怪；
- 状态栏会显示「等待其他窗口完成前台操作…」。

## 四、后台模式（不抢鼠标键盘）

基础页和「多开挂机」页都有「后台模式 / 后台回放」开关，**默认开启**。

开启后：

- 基础挂机：A / 空格 / 技能 / 喝药本来就是 `PostMessage` 后台按键；
- **疲劳检测**：用 `PostMessage` 点击游戏内疲劳图标，不再真实移动鼠标、不切前台；
- **BOSS / 前往BOSS / 返回打怪点录制**：用 `PostMessage` 发送键盘和鼠标事件，
  不移动真实鼠标、不抢前台；
- **多开 BOSS / 回血回放**：同样后台发送，不需要抢前台排队；
- **血量 / 角色名 OCR**：`PrintWindow` 后台截图，不切前台；
- 你可以在前台正常学习、看视频、用浏览器，不会被游戏抢焦点。

要求：

- **游戏窗口不要最小化**：你已经确认最小化会暂停游戏；
- 让游戏窗口保持“不最小化”，放在其它窗口后面即可；
- 部分游戏不处理后台鼠标消息，请先「试放」验证；
- 如果后台鼠标点击无效，取消勾选后台模式，
  程序会恢复“切前台 + 真实鼠标键盘”的回放方式。

说明：

- 后台模式**不会锁定你的键盘鼠标**，你可以正常使用电脑；
- 游戏在后台不会收到你的真实输入，除非你主动把它切到前台；
- 如果游戏必须在前台才处理输入，后台模式无法绕过，这是游戏本身的限制。

### 静止鼠标 / 仅键盘（防抢）

这是后台模式下的一个子模式：

- **只回放键盘事件**；
- 完全跳过鼠标移动、点击、滚轮；
- 不移动真实鼠标、不抢前台；
- 游戏如果自己抢到前台，会尝试把前台还给用户窗口；
- 可以边学习边挂机，键盘脚本继续执行。

限制：

- 录制里的鼠标点击/转镜头不会执行；
- 需要鼠标菜单、鼠标转镜头的录制，请用其它模式；
- 游戏窗口仍然不能最小化（最小化游戏会暂停）。

适合：纯键盘流程、只按技能/喝药/移动键、不需要鼠标点菜单的录制。

## 六、实现要点

- 后台按键：`win32api.PostMessage` + `WM_KEYDOWN/WM_KEYUP`，扫描码和
  `lParam` 按 Windows 规范构造。
- Unity 后台焦点补偿：补发
  `WM_ACTIVATEAPP / WM_NCACTIVATE / WM_ACTIVATE / WM_SETFOCUS`，
  不调用 `SetForegroundWindow`。
- 录制：`mouse.hook` + `keyboard.hook` + 2ms 鼠标按键轮询兜底；
  坐标同时保存屏幕坐标和客户区归一化坐标，换窗口大小也能回放。
- 回放：`SendInput` 鼠标 + `keybd_event` 键盘；每个事件前确认游戏仍在前台，
  鼠标目标点必须在游戏窗口上；结束释放按键并恢复前台/光标。
- BOSS 识别：`PrintWindow` 后台截图 → 裁剪 ROI → RapidOCR →
  解析 `x/y` 或文字消失 → 连续 N 次确认 → 判定击杀。
- 战斗/拾取：复用后台 `PostMessage` 的 `KeySender`，不抢真实鼠标键盘。
- 多开：`SlotRunner` + `ForegroundArbiter`，4 个窗口共享前台操作队列，
  按优先级排队；每个窗口独立打怪/疲劳/血量/回血。
- 角色名：后台 `PrintWindow` 截图 → 裁剪角色名区域 → RapidOCR；
  绑定/刷新窗口时自动读取，显示在每个槽位旁边。
- 血量：`HpMonitor` 后台截图 + OCR，按回血红线/停平A红线分别处理。
- 提醒弹窗：`WS_EX_NOACTIVATE`，置顶但不抢焦点。

## 七、常见问题

### 录制没有录到操作

- 录制时游戏必须在**前台**，鼠标要在游戏窗口内；
- 点击「录制新脚本」后 3 秒内切到游戏；
- 结束时切回本窗口点「停止录制」，或按 `Ctrl+Alt+F8`。

### 回放提示“游戏窗口不在前台” / “鼠标目标点被其它窗口覆盖”

- 回放期间不要切换窗口、不要移动鼠标；
- 关闭遮挡游戏的窗口；
- 如果浏览器抢到前台，程序会主动停止，避免误点。

### 识别战斗一直不结束

- 查看状态栏里的 OCR 结果：“未识别到 BOSS 血量”说明区域没框对；
- 血条没有数字时，把检测方式改成「BOSS 文字/名称」，框住 BOSS 名称；
- 区域越小识别越快、越准；不要把聊天框、技能栏框进去；
- OCR 第一次加载模型需要 1～3 秒，属正常现象；
- 达到「战斗上限」后会自动进入拾取/返回，不会永久卡住。

### 疲劳触发没有自动打BOSS

- 确认基础页勾选了「疲劳检测」并框选了区域；
- 确认「疲劳低于阈值时自动打BOSS」已勾选；
- 确认当前方式需要的录制/检测区域已配置；
- 疲劳每次检测间隔 30 秒，触发后完成后会重新开始计时。

### 多开角色名不显示 / 识别失败

- 先在「多开挂机」页点「框选角色名区域」，框住窗口里的角色名；
- 框选后会自动读取，也可以点「读取全部名字」重试；
- 角色名区域不要框进等级、称号、血条等其它文字；
- OCR 第一次加载模型需要 1～3 秒。

### 多开血量一直显示“血量: --”

- 确认已勾选「启用血量保护」；
- 先点「框选血量区域」，框住当前血量数字；
- 检查每个窗口下面是否选择了回血录制（勾选「需要回血脚本」时必须）；
- 血量识别是后台截图，窗口最小化时会跳过。

### 游戏窗口最小化后还能挂机吗？

**不建议最小化游戏窗口**。你已经确认：这个游戏最小化后会暂停。

- **本程序最小化到托盘**：可以，挂机/多开/热键都会继续；
- **游戏窗口最小化**：程序仍会发后台按键，但游戏暂停后不会真正打怪；
  疲劳/血量/角色名 OCR、BOSS/回血也会暂停或跳过；
- **正确做法**：开启「后台模式（不抢鼠标键盘）」，
  让游戏窗口**不最小化**，放在其它窗口后面；
  这样游戏继续运行，你可以在前台学习/看视频，程序不会抢焦点。

### 录制回放走偏 / 不能完全复刻怎么办？

先检查这几点：

1. **是否用了后台模式**
   后台模式用 `PostMessage` 发鼠标消息，很多游戏不会用它转动镜头，
   录制里有大量鼠标移动时最容易走偏。
   处理：关闭「后台模式」，使用前台绝对模式；
   「前台相对鼠标」会抢鼠标；需要边用电脑请用后台模式。

2. **起始位置/朝向是否一致**
   录制回放不是“自动寻路”，它只是按时间重放键鼠。
   如果回放时角色不在录制起点、朝向不同，同样的操作就会走到别处。

3. **窗口大小是否一致**
   鼠标坐标按客户区归一化保存；窗口大小/宽高比变化会改变镜头转动幅度。
   尽量保持和录制时相同的窗口大小。

4. **游戏是否锁定/隐藏鼠标**
   如果游戏把鼠标锁在屏幕中央，录制时可能只录到很少的鼠标移动。
   保存录制后状态栏会显示“鼠标移动 N 次”；如果 N 很少，
   说明镜头数据可能没录到，当前版本无法完全复刻。

5. **时间精度**
   回放按录制时间线发送；长时间录制、游戏卡顿、速度不是 100%，
   都会让走位产生偏差。建议用 100% 速度，并保证游戏帧率稳定。

6. **按键自动重复**
   新版录制会过滤系统自动重复的 key_down，每个按键只录一次按下/松开。
   旧录制可以重新录一遍，回放会更干净。

### 回环测试结果

仓库里带了 `loopback_test.py`，会启动一个独立测试窗口，录制一段已知键鼠，
分别用前台绝对 / 前台相对 / 后台回放，比较窗口实际收到的消息。

测试结果（本机）：

- **前台绝对**：按键、点击、鼠标位置基本完全复刻（位置误差约 1px）；
- **后台**：测试窗口能收到完全一致的客户端坐标，但真实游戏可能不处理
  后台鼠标消息；
- **前台相对**：会移动真实鼠标、占用前台；本机简单窗口测试受系统加速影响，
  实际效果以游戏为准，无法边用电脑边挂机。

详细事件日志：

```text

%APPDATA%\CreatureCuriosKeyer\player_debug.log
```

### 相对鼠标会抢我的鼠标，能既不抢又准确吗？

纯软件下通常做不到，原因是：

- 后台模式只能用 `PostMessage` 发鼠标消息，游戏如果使用 Raw Input，
  不会处理这些后台消息，镜头不转 → 走偏；
- 相对鼠标必须走 `SendInput`，它会把事件发给**当前前台窗口**，
  并移动真实系统光标 → 必然抢鼠标；
- Windows 没有“只给某个后台窗口注入 Raw Input、同时不动真实光标”的公开 API。

可行方案只有隔离输入：

1. **虚拟机 / 第二台电脑**：游戏和脚本跑在虚拟机/副机，你在主机学习；
2. **虚拟 HID / 硬件宏设备**（如 KMBox、Arduino HID）：游戏看到的是另一个
   USB 鼠标，你的物理鼠标仍然可用；
3. **游戏支持手柄**：可以加虚拟手柄（ViGEmBus）支持，用右摇杆转镜头，
   鼠标完全不占用；
4. 接受取舍：用前台相对模式时不要用电脑；用后台模式时接受镜头可能走偏。

如果你有 KMBox/Arduino 之类的硬件，或者游戏支持手柄，告诉我型号/协议，
我可以再针对那种方式做。

### 录制时闪退

新版把录制用的 Raw Input 隐藏窗口改为**每次实例独立窗口类**，并在停止时注销，
避免旧窗口类指向已释放的 Python 回调导致崩溃。

如果仍然闪退，查看：

```text
%APPDATA%\CreatureCuriosKeyer\crash.log
%APPDATA%\CreatureCuriosKeyer\record_debug.log
```

`crash.log` 会记录未处理异常/原生崩溃；`record_debug.log` 里 `[REC] START`
可以看到崩溃发生在哪一次录制。

- 重新启动本程序再试。

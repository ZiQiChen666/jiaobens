# CreatureCurios 后台按键器 v3.26.1

Windows 桌面小工具：绑定 `CreatureCurios` 窗口后，在后台循环投递 `A`
（可选空格拾取），可选技能、喝药、疲劳检测、定时提醒，支持**自动打BOSS**、**后台回放（不抢鼠标键盘）**，
并支持**最多 4 开**、**血量保护**和**角色名识别显示**；
另外带一个**副本流程**工具（鼠标宏引路 + 后台挂机 + 疲劳联动，见第十节）。

## 安装

要求 Windows + Python 3.10 及以上。

```bat
cd F:\jiaoben\3
pip install -r requirements.txt
```

## 运行

```bat
python creature_curios_keyer.py
```

已打包版本：

```text
dist\CreatureCuriosKeyer.exe
```

> 如果游戏以管理员权限运行，本程序也要右键「以管理员身份运行」，
> 否则 `PostMessage` 可能被 Windows 权限隔离拦截。

## 一、基础挂机

- **绑定窗口**：扫描标题包含 `CreatureCurios` 的可见窗口，选择后点「绑定」。
- **每轮间隔**：默认 250ms，最小 50ms，运行中修改立即生效。
- **循环动作**：`A 按下 50ms → 松开`；
  - 勾选「拾取物品（A 后按空格）」时，再追加 `空格按下 50ms → 松开`；
  - 不勾选时只按 A。
- **技能**：可选自动发送 `1`（12 秒）和 `2`（6 秒）。
- **喝药**：可选自动发送 `Q`，默认间隔 60 秒。
- **疲劳检测**：框选右下角会弹出疲劳提示的图标/按钮，每 30 秒用
  `PostMessage` **后台点击**（不移动鼠标、不切前台）并 OCR 读取 `当前疲劳值:xxx/xxx`；
  个别游戏不处理后台鼠标消息时，可勾选「后台点击读不到时短暂借用鼠标」兜底。
- **疲劳阈值 ±**：默认 800，范围 50～1000；低于 `-阈值` 或高于 `+阈值` 时提醒。
- **定时提醒**：倒计时或指定时刻，最小化到托盘也会弹窗。
- **全局热键**：`Ctrl + Alt + F8` 开始/停止；最小化/关闭窗口驻留托盘。

### 血量自动吃药（Q + W）

单开页和多开页都支持：

- 勾选「血量低于阈值自动吃药（Q+W）」；
- 阈值默认 **1600**；
- 需要先框选血量区域（框住头像旁的当前血量数字）；
- 血量低于阈值时，按「自动喝药 Q」的间隔发送：
  - `Q` 按下/松开；
  - `W` 按下/松开；
- **启用后不再按固定间隔喝药**，只按血量触发；
- 只要血量还低于阈值，就**每隔 Q 间隔继续喝 Q+W，直到血量高于阈值**；
- Q 间隔默认 60 秒，所以两次吃药之间会等待 Q 间隔；想更快可把间隔调小（最小 5 秒）；
- 单开用单开页的血量区域；多开所有窗口共用多开页的血量区域；
- 血量 OCR 失败或窗口最小化时不会触发；
- 游戏窗口请保持不最小化。

## 二、自动打BOSS

BOSS 功能建立在基础挂机之上，**单窗口**运行。有两种方式：

### 方式 A：整段录制回放（推荐，最简单）

把「前往 BOSS → 打 BOSS → 拾取 → 回打怪点」完整录一遍，之后按触发条件
整段回放。

录制：

1. 绑定游戏窗口；
2. 点「录制新脚本」，3 秒内切到游戏；
3. 从站桩点开始完整操作一遍：走到 BOSS、打 BOSS、拾取、返回；
4. 操作完切回本窗口，点「停止录制」；
5. 输入名字保存。

录制只记录**游戏在前台、鼠标在游戏窗口内**的操作，不会录到本程序或其它窗口。

回放：

- 在「录制」下拉框选择刚保存的脚本；
- 点「试放」验证；
- 「打一次BOSS」：只执行一次；
- 「开始BOSS循环」：按「重复」次数执行，`0 = 无限`；
- 「每轮间隔」：两次回放之间等待的秒数；
- 「回放速度」：50%～200%。

> 回放会切换到游戏前台并接管真实鼠标键盘，回放期间不要操作电脑。
> 按 `Ctrl+Alt+F8` 或「停止BOSS」可随时停止。
> 回放前会把游戏切到前台；如果浏览器抢占前台，程序会立即停止，避免误操作。
>
> 如果录制里包含**鼠标转镜头/走位**：
> - 建议关闭「后台模式」，使用**前台绝对模式**；
> - 回放前回到录制时的**起始位置和朝向**；
> - 保持游戏窗口大小和录制时一致；
> - 「前台相对鼠标」镜头更准，但会移动真实鼠标并占用前台，无法边用电脑边挂机。

### 方式 B：识别战斗（导航 + 自动打 + 返回）

录制两小段导航，把战斗交给识别：

1. **前往BOSS录制**（可选）：从打怪点走到 BOSS 前，停止；
2. **返回打怪点录制**（可选）：击杀后拾取并走回打怪点，停止；
3. 在「识别战斗」里分别选择这两段录制（可以不选）；
4. 点「框选区域」，框住能判断 BOSS 是否死亡的区域：
   - **血量数字**：BOSS 血条上的数字，例如 `12345/50000`；
   - **文字/名称**：BOSS 名称或血条文字；
5. 选择「检测方式」：
   - `血量数字`：OCR 解析 `x/y`，当前血量 ≤「击杀血量」时判定死亡；
   - `BOSS 文字/名称`：连续识别不到文字时判定死亡；
6. 设置「连续未识别」次数（默认 2，防止 OCR 抖动误判）；
7. 设置「战斗上限」（默认 180 秒，防止卡死）；
8. 设置「击杀后拾取」次数（默认 3 次空格）；
9. 点「打一次BOSS」或「开始BOSS循环」。

识别战斗流程：

```text
回放“前往BOSS录制”（可选）
→ 用基础页的 A / 技能 / 喝药 自动战斗
→ BossWatcher 每 1.5 秒截图 + OCR 检测
→ 判定击杀：停手 → 按空格拾取 N 次
→ 回放“返回打怪点录制”（可选）
→ 完成一轮
```

识别使用后台 `PrintWindow` 截图，不会移动鼠标；OCR 使用 RapidOCR。

### 触发方式

- **手动**：`打一次BOSS` / `开始BOSS循环`；
- **疲劳触发**：勾选「疲劳低于阈值时自动打BOSS」。
  需要基础页勾选「疲劳检测」并框选区域。
  疲劳 < `-阈值` 时：暂停打怪 → 执行 1 次 BOSS 方案 → 完成自动恢复打怪；
- **定时触发**：勾选「定时打BOSS」并设置分钟数，每隔 N 分钟执行 1 次；
- 疲劳 / 定时触发固定执行 **1 次**；「重复」次数只对 `开始BOSS循环` 生效。

## 三、多开挂机

「多开挂机」页最多同时管理 **4 个游戏窗口**，每个窗口独立执行：

```text
打怪 → 定时检测疲劳 → 疲劳 < -阈值 → 回放 BOSS 录制 → 播完恢复打怪
     → 血量低于回血红线 → 排队回血 / 停平A
```

### 1. 绑定窗口与角色名

1. 先把游戏客户端都打开；
2. 到「多开挂机」页点「刷新窗口」，程序会自动把找到的窗口分配到 4 个槽位；
3. 也可以在每个槽位的「游戏窗口」下拉框手动选择；
4. 先点一次「框选角色名区域」，框住窗口里显示角色名的位置；
5. 之后每次绑定/刷新窗口，程序都会自动 OCR 读取该窗口的角色名并显示：
   - 读取成功：`角色: 张三`（绿色）
   - 读取失败：`角色: 识别失败`（橙色）
6. 也可以随时点「读取全部名字」重新读取。

> 角色名区域和血量区域都是**一次框选、4 个窗口共用**，
> 程序会按每个窗口的客户区尺寸自动缩放。

### 2. 每个窗口的设置

- **BOSS 录制**：该窗口疲劳到阈值时播放的录制；
- **本地挂机**：只后台打怪，不检测疲劳、不播录制；
- **疲劳阈值 ±**：每个窗口独立；
- **喝药间隔**：每个窗口独立；是否喝药仍由单开页「自动喝药 Q」控制；
- **优先级**：1 最高。多个窗口同时要打 BOSS / 回血时排队；
- **回血录制**：每个窗口自己的回血脚本（录制回城 → 回血 → 回打怪点）。

### 3. 血量保护

1. 勾选「启用血量保护」；
2. 点「框选血量区域」，框住头像旁的当前血量数字（如 `1725/1780` 中的 `1725`）；
3. 设置两条线：
   - **回血红线**（高，默认 600，最低 300）：勾选“需要回血脚本”时，
     血量低于它 → 请求回血；不勾选时不会回血；
   - **停平A红线**（低，默认 300）：血量低于它 → 只暂停发 A，
     技能 1/2、喝药 Q 继续；
4. 「需要回血脚本（可选）」：
   - **默认不勾选**：不需要任何回血录制，低血只按停平A红线停手，不播放回血；
   - 勾选后才需要每个窗口选择/录制回血脚本，低血时排队播放回血；
5. 只有勾选「需要回血脚本」后，每个窗口的「回血录制」下拉框和按钮才可用。
   点「录制回血」，3 秒内切到游戏，完整操作一遍回城回血，
   切回程序点「停止录制」并命名。录好的回血脚本只出现在「回血录制」下拉框。

规则：

- 只影响低血窗口，其他窗口继续打怪；
- 如果另一个窗口正在播 BOSS、前台被占用，低血窗口继续打怪，
  回血请求以最高优先级排队；
- 血量掉到停平A红线以下时，该窗口停止发 A，技能/喝药继续；
- BOSS 录制/回血播放期间，该窗口暂停血量检测，不会打断正在播放的录制；
- 回血请求不会切断正在播放的 BOSS 录制。

### 4. 开始 / 停止

- 每个窗口点「开始」，或点「全部开始」；
- 「试放」只播放一次该窗口的 BOSS 录制；
- 「停止」/「全部停止」停止多开；
- 全局热键 `Ctrl+Alt+F8`：
  - 多开运行中 → 停止全部多开；
  - 回血录制中 → 停止录制；
  - 单开 BOSS/挂机中 → 停止对应任务。

> 多开运行期间不能启动单开挂机/自动BOSS；单开运行期间也不能启动多开。
> 同一游戏窗口不能被两个槽位同时使用。

### 5. 前台操作排队

录制回放需要独占前台鼠标键盘，4 个窗口共用 `ForegroundArbiter`；
疲劳检测已改为纯后台 `PostMessage` 点击，**不参与前台排队、不抢鼠标**：

- 同一时间只允许一个窗口执行前台操作；
- 多个窗口同时请求时按 **优先级** 排队；优先级相同按请求先后；
- 其他窗口的后台打怪不受影响，继续打怪；
- 状态栏会显示「等待其他窗口完成前台操作…」。

## 四、后台模式（不抢鼠标键盘）

基础页和「多开挂机」页都有「后台模式 / 后台回放」开关，**默认开启**。

开启后：

- 基础挂机：A / 空格 / 技能 / 喝药本来就是 `PostMessage` 后台按键；
- **疲劳检测**：用 `PostMessage` 点击游戏内疲劳图标，不移动鼠标、不切前台；
  等待提示框期间还会持续补发悬停消息，全程不碰真实光标；
- **BOSS / 前往BOSS / 返回打怪点录制**：用 `PostMessage` 发送键盘和鼠标事件，
  不移动真实鼠标、不抢前台；
- **多开 BOSS / 回血回放**：同样后台发送，不需要抢前台排队；
- **血量 / 角色名 OCR**：`PrintWindow` 后台截图，不切前台；
- 你可以在前台正常学习、看视频、用浏览器，不会被游戏抢焦点。

要求：

- **游戏窗口不要最小化**：你已经确认最小化会暂停游戏；
- 让游戏窗口保持“不最小化”，放在其它窗口后面即可；
- 部分游戏不处理后台鼠标消息，请先「试放」验证；
- 如果后台鼠标点击无效，取消勾选后台模式，
  程序会恢复“切前台 + 真实鼠标键盘”的回放方式；
- 疲劳检测不受后台开关影响，永远走后台点击；
  只有勾选「后台点击读不到时短暂借用鼠标」后，才会在后台点击失败时
  短暂（约 1 秒）移动光标真实点一下，随后立刻还原光标和前台窗口。

说明：

- 后台模式**不会锁定你的键盘鼠标**，你可以正常使用电脑；
- 游戏在后台不会收到你的真实输入，除非你主动把它切到前台；
- 如果游戏必须在前台才处理输入，后台模式无法绕过，这是游戏本身的限制。

### 静止鼠标 / 仅键盘（防抢）

这是后台模式下的一个子模式：

- **只回放键盘事件**；
- 完全跳过鼠标移动、点击、滚轮；
- 不移动真实鼠标、不抢前台；
- 游戏如果自己抢到前台，会尝试把前台还给用户窗口；
- 可以边学习边挂机，键盘脚本继续执行。

限制：

- 录制里的鼠标点击/转镜头不会执行；
- 需要鼠标菜单、鼠标转镜头的录制，请用其它模式；
- 游戏窗口仍然不能最小化（最小化游戏会暂停）。

适合：纯键盘流程、只按技能/喝药/移动键、不需要鼠标点菜单的录制。

## 六、实现要点

- 后台按键：`win32api.PostMessage` + `WM_KEYDOWN/WM_KEYUP`，扫描码和
  `lParam` 按 Windows 规范构造。
- Unity 后台焦点补偿：补发
  `WM_ACTIVATEAPP / WM_NCACTIVATE / WM_ACTIVATE / WM_SETFOCUS`，
  不调用 `SetForegroundWindow`。
- 录制：`mouse.hook` + `keyboard.hook` + 2ms 鼠标按键轮询兜底；
  坐标同时保存屏幕坐标和客户区归一化坐标，换窗口大小也能回放。
- 回放：`SendInput` 鼠标 + `keybd_event` 键盘；每个事件前确认游戏仍在前台，
  鼠标目标点必须在游戏窗口上；结束释放按键并恢复前台/光标。
- BOSS 识别：`PrintWindow` 后台截图 → 裁剪 ROI → RapidOCR →
  解析 `x/y` 或文字消失 → 连续 N 次确认 → 判定击杀。
- 战斗/拾取：复用后台 `PostMessage` 的 `KeySender`，不抢真实鼠标键盘。
- 多开：`SlotRunner` + `ForegroundArbiter`，4 个窗口共享前台操作队列，
  按优先级排队；每个窗口独立打怪/疲劳/血量/回血。
- 角色名：后台 `PrintWindow` 截图 → 裁剪角色名区域 → RapidOCR；
  绑定/刷新窗口时自动读取，显示在每个槽位旁边。
- 血量：`HpMonitor` 后台截图 + OCR，按回血红线/停平A红线分别处理。
- 提醒弹窗：`WS_EX_NOACTIVATE`，置顶但不抢焦点。

## 七、常见问题

### 录制没有录到操作

- 录制时游戏必须在**前台**，鼠标要在游戏窗口内；
- 点击「录制新脚本」后 3 秒内切到游戏；
- 结束时切回本窗口点「停止录制」，或按 `Ctrl+Alt+F8`。

### 回放提示“游戏窗口不在前台” / “鼠标目标点被其它窗口覆盖”

- 回放期间不要切换窗口、不要移动鼠标；
- 关闭遮挡游戏的窗口；
- 如果浏览器抢到前台，程序会主动停止，避免误点。

### 识别战斗一直不结束

- 查看状态栏里的 OCR 结果：“未识别到 BOSS 血量”说明区域没框对；
- 血条没有数字时，把检测方式改成「BOSS 文字/名称」，框住 BOSS 名称；
- 区域越小识别越快、越准；不要把聊天框、技能栏框进去；
- OCR 第一次加载模型需要 1～3 秒，属正常现象；
- 达到「战斗上限」后会自动进入拾取/返回，不会永久卡住。

### 疲劳触发没有自动打BOSS

- 确认基础页勾选了「疲劳检测」并框选了区域；
- 确认「疲劳低于阈值时自动打BOSS」已勾选；
- 确认当前方式需要的录制/检测区域已配置；
- 疲劳每次检测间隔 30 秒，触发后完成后会重新开始计时。

### 多开角色名不显示 / 识别失败

- 先在「多开挂机」页点「框选角色名区域」，框住窗口里的角色名；
- 框选后会自动读取，也可以点「读取全部名字」重试；
- 角色名区域不要框进等级、称号、血条等其它文字；
- OCR 第一次加载模型需要 1～3 秒。

### 多开血量一直显示“血量: --”

- 确认已勾选「启用血量保护」；
- 先点「框选血量区域」，框住当前血量数字；
- 检查每个窗口下面是否选择了回血录制（勾选「需要回血脚本」时必须）；
- 血量识别是后台截图，窗口最小化时会跳过。

### 游戏窗口最小化后还能挂机吗？

**不建议最小化游戏窗口**。你已经确认：这个游戏最小化后会暂停。

- **本程序最小化到托盘**：可以，挂机/多开/热键都会继续；
- **游戏窗口最小化**：程序仍会发后台按键，但游戏暂停后不会真正打怪；
  疲劳/血量/角色名 OCR、BOSS/回血也会暂停或跳过；
- **正确做法**：开启「后台模式（不抢鼠标键盘）」，
  让游戏窗口**不最小化**，放在其它窗口后面；
  这样游戏继续运行，你可以在前台学习/看视频，程序不会抢焦点。

### 回放不如以前准？（鼠标加速导致的镜头放大）

**v3.8.1 已修**：以前用「前台相对鼠标」回放时，Windows 的
「提高指针精确度（鼠标加速）」会把 `SendInput` 的相对位移按速度放大。
本机实测：

```
系统设置：加速=(6,10,1) 指针速度=13
发 dx=100 → 光标实际走了 322px（3.2 倍）
发 dx=20  → 实际 37px（1.85 倍）
小幅位移反过来还会被压缩（dx=1 → 0px）
```

录制抓的是 Raw Input 的**原始位移**（不受加速影响），回放却经过加速，
两边不一致 → 镜头转多/转少、走位偏，录制越长偏得越多。

现在回放相对鼠标时会**临时**把「加速」关掉、指针速度调到 1:1（10），
结束后自动恢复你的原设置；`player_debug.log` 里能看到：

```
ACCEL 回放期间关加速/速度→10（原 accel=(6, 10, 1) speed=13）
ACCEL 恢复 accel=(6, 10, 1) speed=13
```

自检脚本：`python verify_mouse_accel.py`（会显示 3.2 倍 → 1.0 倍的变化）。

想永久关掉加速（不只回放期间）：控制面板 → 鼠标 → 指针选项 →
取消「提高指针精确度」，并把速度滑块调到正中间。

### 录制回放走偏 / 不能完全复刻怎么办？

先检查这几点：

1. **是否用了后台模式**
   后台模式用 `PostMessage` 发鼠标消息，很多游戏不会用它转动镜头，
   录制里有大量鼠标移动时最容易走偏。
   处理：关闭「后台模式」，使用前台绝对模式；
   「前台相对鼠标」会抢鼠标；需要边用电脑请用后台模式。

2. **起始位置/朝向是否一致**
   录制回放不是“自动寻路”，它只是按时间重放键鼠。
   如果回放时角色不在录制起点、朝向不同，同样的操作就会走到别处。

3. **窗口大小是否一致**
   鼠标坐标按客户区归一化保存；窗口大小/宽高比变化会改变镜头转动幅度。
   尽量保持和录制时相同的窗口大小。

4. **游戏是否锁定/隐藏鼠标**
   如果游戏把鼠标锁在屏幕中央，录制时可能只录到很少的鼠标移动。
   保存录制后状态栏会显示“鼠标移动 N 次”；如果 N 很少，
   说明镜头数据可能没录到，当前版本无法完全复刻。

5. **时间精度**
   回放按录制时间线发送；长时间录制、游戏卡顿、速度不是 100%，
   都会让走位产生偏差。建议用 100% 速度，并保证游戏帧率稳定。

6. **按键自动重复**
   新版录制会过滤系统自动重复的 key_down，每个按键只录一次按下/松开。
   旧录制可以重新录一遍，回放会更干净。

### 回环测试结果

仓库里带了 `loopback_test.py`，会启动一个独立测试窗口，录制一段已知键鼠，
分别用前台绝对 / 前台相对 / 后台回放，比较窗口实际收到的消息。

测试结果（本机）：

- **前台绝对**：按键、点击、鼠标位置基本完全复刻（位置误差约 1px）；
- **后台**：测试窗口能收到完全一致的客户端坐标，但真实游戏可能不处理
  后台鼠标消息；
- **前台相对**：会移动真实鼠标、占用前台；本机简单窗口测试受系统加速影响，
  实际效果以游戏为准，无法边用电脑边挂机。


### 相对鼠标会抢我的鼠标，能既不抢又准确吗？

纯软件下通常做不到，原因是：

- 后台模式只能用 `PostMessage` 发鼠标消息，游戏如果使用 Raw Input，
  不会处理这些后台消息，镜头不转 → 走偏；
- 相对鼠标必须走 `SendInput`，它会把事件发给**当前前台窗口**，
  并移动真实系统光标 → 必然抢鼠标；
- Windows 没有“只给某个后台窗口注入 Raw Input、同时不动真实光标”的公开 API。

可行方案只有隔离输入：

1. **虚拟机 / 第二台电脑**：游戏和脚本跑在虚拟机/副机，你在主机学习；
2. **虚拟 HID / 硬件宏设备**（如 KMBox、Arduino HID）：游戏看到的是另一个
   USB 鼠标，你的物理鼠标仍然可用；
3. **游戏支持手柄**：可以加虚拟手柄（ViGEmBus）支持，用右摇杆转镜头，
   鼠标完全不占用；
4. 接受取舍：用前台相对模式时不要用电脑；用后台模式时接受镜头可能走偏。

如果你有 KMBox/Arduino 之类的硬件，或者游戏支持手柄，告诉我型号/协议，
我可以再针对那种方式做。

### 录制时闪退

新版把录制用的 Raw Input 隐藏窗口改为**每次实例独立窗口类**，并在停止时注销，
避免旧窗口类指向已释放的 Python 回调导致崩溃。

如果仍然闪退，查看：

```text
%APPDATA%\CreatureCuriosKeyer\crash.log
%APPDATA%\CreatureCuriosKeyer\record_debug.log
```

`crash.log` 会记录未处理异常/原生崩溃；`record_debug.log` 里 `[REC] START`
可以看到崩溃发生在哪一次录制。

### 全局热键无效

- 可能被其它程序占用；窗口在前台时仍可使用 `Ctrl+Alt+F8`；
- 重新启动本程序再试。

## 十、副本流程（挂机 ↔ 打BOSS 联动）

### 总流程（按疲劳自动切换）

```text
先在「打怪点」挂机（A+技能+喝药+拾取，纯后台 PostMessage，窗口不用在前台）
   ↓ 疲劳 < 下限（默认 -600）
去刷 BOSS 副本：点副本入口 → 进本弹窗 → 进度条 → 副本内 BOSS 点
   → 识别 BOSS 身形 → 打怪 → 血量 OCR 判死 → 拾取 3 次 → 退出副本
   ↓ 疲劳 > 上限（默认 +600）
回到「打怪点」继续挂机 …（一直循环）
```

- **下限 / 上限可以分开填**（「④ 疲劳联动」那一栏）：疲劳 `< 下限` → 去打 BOSS，
  `> 上限` → 回打怪点打小怪。
- **严格滞回，不会来回跳**：
  - 正在打小怪：只有疲劳 **跌破下限** 才去 BOSS；中间区间（比如上限 800、现在 700）继续打怪；
  - 正在打 BOSS：只有疲劳 **涨过上限** 才回打怪点；打完 BOSS 时疲劳 700 也不会立刻又跑回去打BOSS。
- **不设挂机时长**：打怪点一直打，每 `查疲劳间隔`（默认 **90 秒 = 1 分半**）读一次疲劳；`< 下限` 才去打 BOSS。
- **打怪是纯后台**：打怪点到位后会把前台还给你，A/技能/拾取全走 `PostMessage`，
  窗口不用在前台、鼠标也不用在游戏里（只有「点地图点位」那一下需要借鼠标）。
- 不想要联动：把「打怪点挂机 ↔ 打BOSS 联动」勾掉 → 只跑 BOSS。

### 输入模式：混合（推荐）

| 模式 | 点击（地图点/弹窗/仓库） | 按键（A/技能/Q/ESC…） | 占用你的电脑 |
| --- | --- | --- | --- |
| **混合（默认）** | 临时把游戏切前台 + 借走光标点一下，**点完立刻把光标和前台还原** | 后台 `PostMessage` | 只有点击的那一下 |
| 前台 | 全程切前台 + 真实鼠标键盘 | 真实按键 | 全程占用 |
| 纯后台 | `PostMessage`（有些游戏不认，会出现“开了地图就不动”） | 后台 | 不占用 |

混合模式下：

- 等待寻路、等加载、打怪这些**纯键盘阶段会把前台还给你**（`release_focus`），
  你可以正常用浏览器/其它软件；
- 只有真正要点击的时候（点副本入口、点「进入游戏」、点 BOSS 点、点仓库、点退出）
  才切前台 + 借光标，点完马上还原光标**和前台**，回到你原来的窗口；
- 键盘事件全程后台投递，不依赖鼠标在哪；
- 真实点击那一下（不到 0.5 秒）可以**临时屏蔽你的鼠标/键盘**（勾「点击时短暂屏蔽外部鼠标键盘」），
  防止你正好动鼠标，把这一下点到别的窗口上；点完立刻恢复。
  需要本程序以管理员运行（`BlockInput` 要管理员权限）；如果勾了之后点击失效，就取消勾选。

### 多开时怎么不互相干扰

每个窗口的按键都是 `PostMessage`，互不影响；会互相影响的只有三件事：

1. **「点地图/进本/退本」那一下要借真实鼠标** → 会短暂抢一次前台，
   别的窗口的游戏在这一下可能掉几帧、丢一两个按键（就是"节奏乱了"的感觉）。
   - 多开建议把「输入模式」改成 **纯后台**（游戏认的话完全不抢前台）；
   - 必须借鼠标时，勾上 **「点击时短暂屏蔽外部鼠标键盘」**，并且别让几个游戏窗口**重叠**；
   - **「前台」模式只适合单开**（它本来就设计成全程占用）。
2. **OCR 引擎是共用的**（血量判死）：拿不到锁的窗口现在会**直接跳过这一轮**，
   不会再站那儿等 0.5 秒，所以不会卡住攻击节奏；跳过不计漏读，不会误判死亡。
3. **记前台时会忽略"别的游戏窗口"**：多开时不会把兄弟窗口抢到前台
   （以前会把 A 的打怪窗口顶到最前面，造成互相打断）。

多开借鼠标时，日志会多一行提示：

```text
多开提示：现在是「借真实鼠标点击」模式，几个窗口会互相抢前台，打怪节奏容易被打断。
多开建议把「输入模式」改成『纯后台』（或者至少勾着「点击时短暂屏蔽外部鼠标键盘」）
```

### 是否允许抢占鼠标键盘（关键开关）

参数区有一个复选框：**允许抢占鼠标键盘**（默认**不勾**）

| 状态 | 行为 | 什么时候用 |
| --- | --- | --- |
| **不勾（默认）** | 纯后台：只发 `PostMessage`，**不切前台、不动光标** | 你人不在 / 要边挂边用电脑 / 多开 |
| 勾上 | 需要点击时才切前台 + 借光标点一下，**点完立刻还原光标和前台** | 你在电脑前，点地图更保险 |

配合「输入模式」下拉（混合 / 前台 / 纯后台）一起用：不勾抢占时，无论选哪个都是纯后台。

> 后台打怪的关键：每次按键前会补发 `WM_ACTIVATEAPP / WM_NCACTIVATE / WM_ACTIVATE /
> WM_SETFOCUS`（让游戏以为自己是激活的），并把按键投递到**真正接收键盘的子窗口**
> （Unity 常把焦点放在子窗口上），这就是后台窗口能自己平A的原因。

### 挂机不再设时长（按疲劳循环）

- **不设挂机时长**（多开那 4 行也没有秒数了）：一直打，每 `查疲劳间隔`
  （默认 **90 秒 = 1 分半**）读一次疲劳；
- `疲劳 < 下限` → 结束挂机，去打 BOSS；
- 打 BOSS 途中 `疲劳 > 上限` → 这轮 BOSS 收尾（拾取 → 退本），下一轮回打怪点继续挂机；
- 不再有 `farm_seconds` 这个挂机时长；多开时每个窗口各自每 90 秒查自己的疲劳。

### 快捷键 F8 / F9

- **F8**：开始运行；多开 4 行里已选窗口会**全部开始**，一行都没选就启动单窗口
- **F9**：停止（停止单开 + 多开所有窗口；正在录引路宏时先停录制）
- 全局生效（最小化到托盘也能用）；注册失败会在日志里写明。

### 自动喝药（两种，可同时开）

**① 低于血量阈值喝药**

- 先点「框血量区域」框住角色血量数字（如 `1725/1780`）；
- 勾上阈值（「血量阈值」填数字，例如 1600）；
- **血量 < 阈值** → 每 `喝药间隔`（默认 **6 秒**）按一次 **「喝药键」**，
  默认是 `q,w,e`（依次按，可在「喝药键」里改成任意多个，用逗号隔开）；
- 一直喝到**血量 > 阈值就自动停**；血量又掉下去会接着喝；
- 日志：`血量 1169 < 1608 → 喝药「q、w、e」（每 6s 一次，血够了就停）`；
- 开打时会先打一行确认配置：
  `自动喝药：血量 < 1617 → 每 6s 按「q、w、e」，血够了就停`
  （填了阈值但没框区域会明确提示「不会按血量喝」）；
- 第一次读血量会打 `血量识别 OK：1169/1841（阈值 1617）`；
  读不到会打 `血量识别失败：…（区域 …）`，方便排查框选；
- 没框血量区域时按固定间隔喝（保守策略）。

**② 定时喝药（不管血量）**

- 勾「定时喝药（不管血量）」+ 每 `N` 秒（默认 **60 秒**）；
- 开打先按一次，之后固定间隔按「喝药键」（同样默认 `q,w,e`）；
- 适合 60 秒的 buff 药；打怪和打BOSS 两个阶段都生效；
- 日志：`定时喝药：开打先按一次「q、w、e」，之后每 60s 一次`。

> - 血量 OCR 每次都**现拍一张**，并且和 BOSS 血量 OCR 共用一把锁：
>   多开时不会两个 OCR 同时跑，也不会再拿进本前的旧截图判血量。
> - 多开抢不到 OCR 时：先不阻塞抢、再等 0.6 秒，还抢不到就**这轮跳过**；
>   连续 3 次读不到就**兜底按固定间隔喝药**（日志：`血量连续 3 次读不到
>   （可能别的窗口在 OCR）→ 先按固定间隔喝药兜底`），不会见死不救。
> - 每个窗口、每场战斗都会打一次 `血量识别 OK：1169/1841（阈值 1617）`，
>   多开时四个窗口各自都有自己的这一行。

### 一键放入仓库

打完 BOSS、退出副本之后自动执行：

```
点「仓库图标」→ 等 0.5s + 界面出来 → 点「一键放入」→ 等 0.5s
→ 按 ESC（1/2）→ 等 0.5s → 按 ESC（2/2）→ 等 0.5s
```

- 要标 2 个点位：**⑥ 仓库图标**、**⑥「一键放入」按钮**；
- ESC 次数默认 **2**（不多不少，可调 0~5）；每步缓冲默认 **0.5s**；
- 勾掉「打完 BOSS 一键放入仓库」就不做这一步。

### 单次 BOSS 流程（打 BOSS 那一半）

```text
点副本入口(地图1) → 立刻盯「进入弹窗」(出现就点，3s 没识别到先盲点)
→ 加载进度条 ≥90% 才算进本 → 点副本内 BOSS 点(地图2)
→ 等画面静止 → 识别「BOSS 身形」(10 张样本 + 滑动搜索) → 挂机打怪
→ BOSS 血量图标连续 3 次不见 = 打完 → 拾取 3 次 → 缓冲 1s → 退出副本 → 缓冲
```


```text
① 点副本入口（地图1）     点完就开始「边走边看」弹窗（寻路途中每秒都在识别）
     · 弹窗一出现 → 点「进入游戏」
     · 识别不到 → 3 秒后先盲点一次「进入游戏」（不再傻等）
② 加载进度条              连拍多帧量填充比例，≥90% 才算真的进本
     · 没看到进度条 → 认为没进副本 → 重新寻路（最多 3 次）
③ 副本内 BOSS 点（地图2）  点它 → 等寻路
④ 等停下再识别「BOSS 身形」 走路时画面在动 → 不识别；画面静止 0.8s 后才开始比对
     · 支持 **10 张 BOSS 样本**：任一张像就算命中（不同角度/动作都能认）
     · 不像 → 回第 ③ 步重新寻路（≤3 次）
     · 没识别到 → 回到第 ③ 步重新寻路（最多 3 次）
⑤ 挂机打怪                每次平A后立刻拾取 + 技能 + 低血喝药
     · 监控「BOSS 血量图标」：开打时拍下它的样子，连续 3 次不像了 → 判定 BOSS 已死
     · 没框图标就按时间上限停
⑥ 拾取 3 次 → 缓冲 1s → 点「退出副本」→ 识别「退出确认弹窗」→ 点「确认」→ 等加载 → 缓冲
```

动作之间统一 **缓冲 1 秒**（可调）：进本后、到点位后、拾取后、退出后。

### 识别优化（v3.14：弹窗/BOSS 身形老识别不到？）

**弹窗识别**原来是单阈值（0.90）像素比对，弹窗字一变、有动画就永远差一点 → 只能等超时。
现在改成：

- **两条路任一命中就算**：`相似度 ≥ 0.80` 或 `相似度 ≥ 0.60 且区域内容占比 ≥ 5%`；
- 轮询从 0.5s 提到 **0.2s**（更灵敏）；
- 每秒打印一次实测值，方便调：
  `等进入弹窗… 相似度 0.62 / 占比 0.41`
- 读旧标定时会**自动把 0.90 放宽到 0.80**，并补上宽松阈值；
- 界面上还能手动调「识别相似度 / 宽松阈值」（老识别不到就调到 0.70 / 0.50）。

**BOSS 身形**原来只比原位、差几像素就不认。现在：

- 框选 BOSS 后会在**放大 1.6 倍的区域里滑动搜索**最像的位置（BOSS 走两步、晃一下也能中）；
- 单格容差从 18 提到 **30**（抗技能特效/受击变色）；
- 阈值 0.60（命中约 0.67+，没 BOSS 是 0.00，实测不误判）；
- 判定失败会打印 `没等到BOSS 身形（最高相似度 0.42…）`，一眼看出是"没到"还是"差一点"。

### BOSS 身形：采 10 张样本

1. 先点「框选」把 **BOSS 本体**框住（框身上不动的部分，别框特效/飘字）；
2. 站在 BOSS 面前点 **「采样本」** → 自动连拍 **10 张**（每 0.3 秒一张）；
3. 按钮会显示「样本 N 张」；BOSS 在动/换动作时可以**再点几次**继续累积；
4. 识别时拿这 N 张逐个比（还带 ±1.6 倍范围的滑动搜索），**任一张够像就算找到 BOSS**。

> 走路过程中画面一直在变，程序**不会**去识别；等角色停下（画面静止 0.8 秒）
> 才开始比对，所以不会把路过的场景误判成 BOSS。

### BOSS 死亡判定（OCR 读血量，和主程序 BossWatcher 同一套）

打 BOSS 时对**你框的那块区域**做 OCR，读「BOSS 名字 + 当前/最大血量」：

| `farm.boss_hp.mode` | 怎么判 | 说明 |
| --- | --- | --- |
| **`ocr`（默认）** | 读到 `15966/18000` → 还活着；读到 `0`（或 `≤kill_hp`）→ 死；连续 `miss` 次读不到（血条/名字消失）→ 死 | 和主程序「自动打BOSS」用的是同一个 `BossWatcher` 算法 |
| `bright` | 区域亮像素占比 `< min_fill`（0.15）连续 `miss` 次 → 死 | v3.24.0 tag 的老办法，要求框里「活着亮、死了暗」 |
| `icon` | 开打拍基准，同色占比 / 结构相似度都不像了 → 死 | 只在标定里写 `use_icon: true` 才启用 |

OCR 模式参数（保存在标定 `farm.boss_hp` 里）：

- `ocr_every`：每 **2 秒**读一次（单次约 0.4s；4 开时可调到 3.0）；
- `grace`：开打前 **6 秒**先不判死（血条/名字可能还没弹出来）；
- `miss`：连续 **3 次**读不到才判死（偶发 OCR 失败不会误杀）；
- `kill_hp`：血量 ≤ 这个值就算死（默认 0）。

日志（一眼看出 OCR 有没有在工作）：

```text
[副本] 判死方式：OCR 读 BOSS 血量（每 2.0s 读一次，连续 3 次读不到 = 打完）
[副本] BOSS 血量 OCR 已生效：血量 18000
[副本] 血量监测（10s）：血量 15966 / BOSS身形相似 0.91
[副本] 血量监测（20s）：血量 8421 / BOSS身形相似 0.90
[副本] BOSS 血量图标不见了（1/3）（OCR 没读到血量（空））
[副本] BOSS 血量图标连续 3 次不见 → 判定打完
```

> - **打死不判死**：通常是血条数字没被 OCR 读到 → 用「看一眼当前判定」看 OCR 读到什么，
>   把框收紧到血条文字/名字上；也可以把 `miss`、`grace` 调大。
> - **没死就判死**：把 `miss` 调大（3→4）、`ocr_every` 调小（2.0→1.0）。
> - 想回到老办法：把 `mode` 改成 `bright`（阈值 `min_fill`）。
> - 「看一眼当前判定」会显示 `BOSS血量图标=亮度 xx% / 内容 xx% / 同色 xx% / 图标相似度 xx%`。

### 打怪点：按疲劳分流（BOSS / 打小怪）

两个数分开填（「④ 疲劳联动」里的 `疲劳下限` / `疲劳上限`，都能填负数）：

| 疲劳值 | 做什么 |
| --- | --- |
| 打小怪时 `< 下限`（默认 -600） | **去打 BOSS**（上限 `打BOSS上限`，最大 1000s；血量 OCR 判死提前结束） |
| 打BOSS时 `> 上限`（默认 +600） | **回打怪点打小怪**（不设时长，一直打） |
| 上限与下限之间 | 保持当前分支，不来回跳 |

- 每 **90 秒**（1 分半）查一次疲劳（`查疲劳间隔` 可改）；多开时每个窗口各自查自己的。
- 打小怪时疲劳掉到 `下限` 以下 → 当前挂机立刻结束，下一轮去 BOSS；
- 打BOSS时疲劳涨到 `上限` 以上 → **当前这轮打完后收尾**（拾取 → 退本），
  下一轮回打怪点，不会来回跳（滞回）。
- 例：`下限 -800` + `上限 400` = 打到 -800 才去刷 BOSS，回到 +400 就收工回来打小怪。

### 识别时机：画面不动了才开始比对

走路/攻击时每帧都不一样，用那种帧比相似度必然偏低（这也是一直识别不到
「进入弹窗 / BOSS 身形」的主要原因）。现在统一改成：

- **必须连续 `still_seconds`（默认 0.8 秒）画面都没动**（相邻帧差异 ≤ `still_diff`），
  才开始比对；比对还要**连续 3 帧命中**才算识别到；
- **画面在动就一律不判定**——绝不再拿"最像的一帧"兜底（就是那个会把
  路过的小怪认成 BOSS 的坑）；超时还在动就直接判"没到"，回地图重点 BOSS 点；
- BOSS 身形判定还加了严格下限：相似度要 **≥ `max(sim, min_sim=0.75)`**，
  不再走「相似度 ≥ 0.60 且区域有内容」的宽松兜底（小怪相似度常在 0.6~0.7）；
- 小鹿是"到点那一刻"的样子，打起来变大鹿 → 只在到位时认一次，
  开打后判死只靠血量 OCR；
- 日志：`画面静止后识别到 BOSS 身形（相似度 0.88 / 占比 0.22 / 画面差异 0.004）`、
  `画面一直在动，没敢判定 BOSS 身形（最高相似度 0.72）→ 回地图重点`。
- 站立时环境小动画（树叶/粒子）也会让帧有差异，所以 `still_diff` 默认放宽到
  **0.05**（走路是 0.2 以上，不会混）；老标定里 0.015 的会自动升到 0.05。

### 进本进度条：测不到不再"回地图重进"

- 进度条量法改成两路取最大：
  1. **静态**：以上/下两行的**众数色**当背景，看多少列和背景不同；
  2. **对比第一帧**：和"加载刚开始那一帧"比，多少列变了（框得只剩条子也能量）。
- 两路都不行（完全测不到条子）时：**已经点过「进入游戏」就先按已进本继续**，
  走到 BOSS 点再看结果；不会再因为"量不出进度条"反复回地图重进。
  日志：`没测到加载进度条 → 但已经点过「进入游戏」，先按已进本继续`；
- 如果明明量到了条子但没到 90%，还是照旧算没进本（回地图重进）。

### BOSS 分身（一个副本要打 3 只）

有些 BOSS 是 **3 个分身**，要全打完才算通关、才能退出副本。界面上：

```
[✓] BOSS 有分身（打完继续打下一只）   一共打 [3 只]
```

- **不勾**：按普通 BOSS 走 —— 打完一只 → 拾取 → 退出副本；
- **勾上**：打完一只后**不退出**，回地图重新点 BOSS 点打下一只，直到打完 N 只，
  然后才拾取 → 退出副本（只退一次、仓库也只放一次）；
- 每只的判死都是独立的（血量 OCR 重新拍基准），日志：
  ```
  本副本要打 3 只 BOSS（分身怪）
  —— BOSS 分身 1/3 ——
  ...
  —— BOSS 分身 2/3 ——
  ```

### 用久了会不会越来越卡（v3.25.17 修了）

排查出四个会"越用越卡"的点，都处理了：

| 问题 | 说明 | 修法 |
| --- | --- | --- |
| **日志控件无限增长** | `QPlainTextEdit` 只 append 不限制 → 跑一晚上几万行，每次 append 都要重排整篇；而且 undo 栈把每一行都存一份 | 只留最近 **1500 行**、关掉 undo/redo、不折行 |
| **改参数就写盘** | 拖数值时 `valueChanged` 连发，每次都把整个方案 JSON 写一遍 | 加 **500ms 防抖**，停手才写 |
| **runs 截图无限攒** | 每杀一只 BOSS 存 1.3MB 的 png，跑一晚上几个 G | 只保留最近 **200 张** |
| **OCR 线程反复起停** | 每次 `combat()` 都新建线程 | 任务没变就**复用**同一个线程 |
| **OCR 频率太高（4 开吃 CPU）** | 玩家血量/BOSS 血量原来 2 秒读一次 | 默认改成 **3 秒**（旧标定自动升级） |

另外：
- 角色名 `NameReader` 线程用完 `deleteLater()`，不会再挂在页面上；
- 如果还是觉得鼠标"顿一下"，可以把「点击时短暂屏蔽外部鼠标键盘」取消勾选
  （那个是真点击时临时 `BlockInput`，需要管理员，个别系统会有感）。

### 挂机时为什么不再"平A一顿一顿"

以前血量 OCR 是在**攻击循环里同步做**的（截图 0.1~0.3s + OCR ~0.5s），
所以每 2 秒就会停一下，手感就是"每次平A都卡一下"。现在：

- 玩家血量、BOSS 血量 OCR 全部丢到**后台线程**（`_OcrWorker`），
  按 `hp_check_every` / `ocr_every` 自己读；
- 攻击循环只读**缓存**（`hp_now()` / BOSS 血量），永远不会被截图/OCR 卡住；
- 截图加了窗口级锁，后台线程和主线程同时截图也不会打架；
- 多开时 OCR 仍然串行（共用一把锁），但都是"抢不到就跳过"，不会排队等。
- 自检：`verify_dungeon_flow.py` 里有一条 —— 把 OCR 故意拖慢 0.3 秒，
  跑 3 秒挂机真实耗时仍 < 1.5 秒，且中途一直在按 A。

### 打怪：纯后台挂机（窗口不用在前台）

这是「第二部」——打小怪那段和主程序的挂机一样，**不需要鼠标在游戏窗口里、也不需要游戏在前台**：

- 到了打怪点（那一下要借鼠标点地图）之后，程序会**立刻把前台还给你**；
- 打小怪期间的 `A` / `技能 1` / `技能 2` / 拾取 / 喝药 全部是
  `PostMessage` 后台投递，先补 `WM_ACTIVATEAPP / WM_NCACTIVATE / WM_ACTIVATE /
  WM_SETFOCUS`，再把按键发给**真正接收键盘的子窗口**（Unity 常见）；
- 所以你可以正常用浏览器/别的软件，鼠标也不用留在游戏窗口里；
- 日志会写：`打怪点挂机：A/技能/拾取全部后台 PostMessage 发送（窗口不用在前台，鼠标也不用在游戏里）`
  和 `已把前台还给你（挂机按键继续走后台 PostMessage）`；
- 如果游戏还是不认后台按键：① 本程序和游戏都用**管理员**运行；② 窗口别最小化；
  ③ 到「引路宏」那一行点「测试后台平A」看是否发送成功。
- 引路宏的点击每一步都会单独抢一下鼠标，多开时两个窗口的宏会交错执行，
  所以不建议同时开 3~4 个都带引路宏的窗口。
- 界面上只有 `打BOSS上限` 一个时间参数（5~1000 秒，血条一直不消失时兜底）；
  **没有挂机时长**。

### 引路宏（鼠标宏，地图点不准时用）

副本页参数区新增「引路宏」：

1. 站在打怪点，点 **「录制引路宏（3 秒后开始）」**；
2. 3 秒内切到游戏，正常操作：开图 → 点副本入口 → 点「进入游戏」→ 跑到 BOSS；
3. 切回本程序点 **「停止并保存」**（或按 F9）；
4. 勾上 **「用引路宏导航」**。

运行时，进本 + 跑向 BOSS 这两步直接回放录制的鼠标宏，不再依赖地图点位：

- 只录**左键点击和按键**（鼠标移动/拖拽不录，**长按也只算一次点击**），
  坐标是窗口客户区归一化坐标，换分辨率/窗口大小也能用；
- 允许抢占时：每次点击借一下鼠标+前台，点完立刻还原；不允许抢占时：走后台消息；
- 宏跑完会等角色停下、识别「BOSS 身形」；没识别到可以选择
  **「宏跑完没到 BOSS 时，回退到地图点位」**；没勾回退时，会先尝试
  「拾取 → 退出副本」兜底，避免下一轮从副本内部开始放宏、全程点错；
- 勾了引路宏且已录制时，开跑前的检查不再要求「副本入口 / 进入游戏 /
  BOSS 点」这三个地图点（勾了「回退」才会反过来要求）；
- 地图点位重试时也会在标记点周围 2% 半径绕圈微调（V3.2 的做法）；
- **点歪了会自己收回来**：
  - 进本时超过 `等弹窗` 时间还没看到「进入游戏」弹窗 → 先按 ESC 把可能开着的
    界面关掉，**回地图重新点副本入口**（最多 `没弹窗重试` 次，带微调）；
  - 到 BOSS 点后等不到「BOSS 身形」→ 同样 ESC + 回地图重点 BOSS 点；
  - 这样就不会出现"上一次地图还开着 → 再按 M 反而把地图关掉 → 那一下点进游戏世界、
    角色乱走"的问题。日志会写 `回收界面：进本超时（可能点歪了，或者地图没开）`。

### 后台平A自检

「引路宏」那一行有 **「测试后台平A」**：给当前绑定窗口发一次后台 A，
日志会写目标窗口/焦点子窗口。游戏没反应时依次检查：管理员运行、窗口别最小化、
勾「允许抢占鼠标键盘」。

### 副本方案（命名保存 / 切换）

页面最上面一条：`当前方案 [下拉] [保存副本] [重命名] [删除]`

- **保存副本**：把当前这套标定 + 全部参数（时间、循环、骑乘、轮数…）存成一个命名方案；
  之后改任何参数都会**自动写回当前方案**，下次打开默认就是它
  （第一次会弹窗让你起名字，比如「幽暗森林」「小号专用」）；
- **切换方案**：下拉换一下，点位/区域/时间参数立刻整套换掉；
- **重命名 / 删除**：改名字、删掉不要的；
- 文件位置：`%APPDATA%\CreatureCuriosKeyer\dungeons\<名字>.json`，
  当前用哪个记在 `dungeon_active.txt`，下次打开自动读那一个；
- 「（未命名/当前标定）」= 还没存过方案时的默认文件。

### 手动微调（同一个页面，黑字白底）

- **点位**：副本入口 / 弹窗「进入游戏」/ BOSS 点 / 「退出副本」(第一下) /
  「确认」(第二下) / 疲劳图标，每项一个「设置」按钮（地图类会先按开图键）；
- **时间参数**：走进副本 40s / 等弹窗 20s / 没弹窗重试 3 次 / 进本加载 10s /
  跑向BOSS 30s / 打BOSS上限 120s（最大 1000s）/ 退出后加载 10s / 每轮间隔 / 喝药 6s / 拾取 8s；
- **疲劳**：不设挂机时长；打小怪时疲劳 < 下限 去打BOSS，打BOSS时疲劳 > 上限 回打怪点；每 90 秒查一次；
- **运行**：绿底大按钮「▶ 开始运行」，旁边有「看一眼当前判定」「试跑一轮（不按键）」「停止」。

### 多开（每行显示角色名）

「多开」那 4 行现在长这样：

```
窗口1  [窗口下拉]  角色: 星陈      [开始]  未运行
窗口2  [窗口下拉]  角色: 蔓角灵鹿  [开始]  未运行
```

- 会自动**排除本程序自己的窗口**（标题含“后台按键器”或属于本进程），

- 刷新窗口列表 / 切换窗口时会自动读；也可以点工具条上的 **「读取名字」** 一键全读；

### 多开（不设挂机时长，纯疲劳驱动）

每行每 90 秒查一次**自己窗口**的疲劳，`< 下限` 去 BOSS、`> 上限` 回打怪点。
多开时所有窗口共用一把输入锁：只有要点击/切前台的那一下才排队，
其他窗口继续后台平A，不会互相抢鼠标。

### 注意事项

- 框区域时**比目标松一圈**（四周留背景边），否则目标铺满整块区域时占比会算成 0；
- 地图可拖动/缩放的，标定前先把地图调到固定视角；
- 游戏窗口不要最小化；PrintWindow 抓不到会记"截图失败"并跳过；
- 没框「进本弹窗区域」也能跑：会直接盲点一次「进入游戏」按钮（日志会说明）；
- 疲劳检测不框区域时，会沿用主界面「疲劳检测」页框过的疲劳区域。
- **点住不放再读**：疲劳提示框需要鼠标停在图标上才会出现，所以点完
  **光标会留在图标上** `hold_seconds`（默认 **3 秒**，可在标定里改），
  期间每 `poll`（0.3 秒）截一次图，**读到就提前结束**；
- 还是读不到就**再点一次**（`retry`，默认 2 次，每次仍然是点住等 3 秒），
  读完后立刻把光标/前台还给你；
- 日志：`疲劳：点住 3s 没读到（未识别到疲劳文本）→ 再点一次`。
- **读疲劳的时候不会停下**：这 3 秒里照样发平A（和拾取），角色不会站着发呆。


## 十一、跨图打BOSS（图2 挂机 → 图1 打BOSS → 回图2）

主界面新增分页 **「跨图打BOSS」**（和「副本流程」分开存标定：
`%APPDATA%\CreatureCuriosKeyer\cross_profile.json`）。

先把这几个东西标好，就能跑：

| 步骤 | 做什么 |
| --- | --- |
| **① 图2 打怪点** | 角色站在图2 → 点「标定/改点」（自动按开图键截图）→ 图上点打怪位置。<br>可以标**多个**，用下拉框切换；每个有自己的「寻路等待」 |
| **② 去程路径（图2 → 图1）** | 「＋ 加点击」在图上点传送点/入口；「＋ 加按键」加个 `esc` 之类的；每步都能改「等 N 秒」、上移/下移/删除 |
| **③ 图1 副本（进本 / 退本）** | 勾「自动进入副本 / 自动退出副本」（默认都勾）；标 4 个点：**副本入口 / 进入游戏 / 退出副本 / 确认**；可选框选：进本弹窗 / 加载进度条 / 退本确认弹窗；填进本寻路、等弹窗、进本加载、退本加载 |
| **④ 图1 BOSS** | 点「标定」→ 在图上点 BOSS 位置；「框选」BOSS 身形（可「采样本」连拍 10 张）、「框选」BOSS 血量；填寻路等待、BOSS 上限、是否分身 |
| **⑤ 回程路径（图1 → 图2）** | 同样加点击/按键；跑完会自动再点一次①里选中的打怪点，接着挂机 |

参数里还有：疲劳下限/上限、查疲劳间隔、喝药（阈值 + 按键 + 间隔）、技能、平A后拾取、每轮间隔。

运行逻辑（一轮）：

```
图2 选中的打怪点挂机（后台按键）→ 疲劳 < 下限
  → 走「去程路径」到图1
  → **进入副本**（点副本入口 → 等进本弹窗 → 点「进入游戏」→ 等进度条）
  → 点图1 BOSS 点 → 打 BOSS（判死/喝药/拾取同副本流程）
  → **退出副本**（点「退出副本」→ 点「确认」→ 等加载）
  → 走「回程路径」回图2 → 自动点回打怪点 → 继续挂机 …
```

- 进本/退本默认是**自动**的（③ 里两个勾选框）。也可以取消勾选，改用路径里的
  **「＋ 进本 / ＋ 退本」** 把这两步插到任意位置（比如"先点传送 → 进本 → 再点一个点"）。

- 判死、喝药、技能/拾取、画面静止才识别 BOSS 这些能力**全部复用副本流程**那套；
- 进本=副本流程里的 `enter_dungeon`（含"没识别到弹窗就先盲点一次""量不到进度条就按已进本继续"），
  退本=`exit_dungeon`（含"没识别到确认弹窗就再点一次退出副本"）；
- 图2 打完 BOSS **不做「一键放入仓库」**（需要的话说一声，我加）；
- 跑之前会检查：打怪点 / 去程 / BOSS 点 / 回程 有没有标全，缺什么直接弹窗告诉你；
- 想先看流程不按键：点「试跑一轮（不按键）」。
